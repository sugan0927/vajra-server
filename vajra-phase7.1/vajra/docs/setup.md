# `vajra setup`

Interactive wizard that generates `/etc/vajra/app.toml` for a fresh
WordPress deployment.

```sh
sudo vajra setup
sudo vajra setup --config /tmp/scratch.toml   # dry run
```

## Prompts

| Prompt | Default | Used for |
|---|---|---|
| Domain | required | TLS cert path, comment in generated file |
| Admin email | empty | stored as a comment (future ACME) |
| PHP version | last `/etc/php/X.Y` | derives `unix:/run/php/phpX.Y-fpm.sock` |
| Using Redis? | no | adds a comment block about `php.ini` + drop-in |
| Enable auto-backup? | yes | adds `[backup]` + `[backup.database]` |
| Enable rate limiting? | yes | adds `[rate_limit]` |
| Rate limit (rps) | 50 | `[rate_limit].rps` |

PHP versions are detected by listing `/etc/php/` and keeping only
directories of the form `X.Y`.

## Output

The wizard writes a commented TOML file. Example for `example.com`,
PHP 8.2, backups + rate limit on, Redis off:

```toml
# /etc/vajra/app.toml - generated by vajra setup
#
# domain:  example.com
# email:   admin@example.com (for future ACME cert issuance)
# php:     8.2 -> /run/php/php8.2-fpm.sock
# redis:   no

[server]
listen     = "0.0.0.0:80"
workers    = 0
pin        = true
grace_secs = 5

# [tls] - uncomment once certs exist (Let's Encrypt):
# listen = "0.0.0.0:443"
# cert   = "/etc/letsencrypt/live/example.com/fullchain.pem"
# key    = "/etc/letsencrypt/live/example.com/privkey.pem"

[static]
root = "/var/www/html"

# FastCGI route to PHP-FPM.
[[proxy]]
prefix    = "/"
upstreams = ["unix:/run/php/php8.2-fpm.sock"]
balance   = "round_robin"

[rate_limit]
enabled = true
rps     = 50
burst   = 100

[backup]
enabled      = true
schedule     = "0 0 3 * * *"
keep_days    = 7
destinations = ["local"]
local_dir    = "/var/backups/vajra"

[backup.database]
host = "localhost"
user = "root"
name = "wordpress"
```

## Overwrite behaviour

If the target path already exists the wizard asks once:

```text
/etc/vajra/app.toml already exists - overwrite? [y/N]:
```

Answer `n` (or press Enter) to abort; the file is left untouched and
the exit code is non-zero.

## Validation

After writing, run:

```sh
vajra --check --config /etc/vajra/app.toml
```

`vajra setup` does not run the checks itself - keeping the two
commands orthogonal lets `--check` be the single source of truth for
validation (and testable without a wizard).

## Non-goals

* No live probing of PHP-FPM or MySQL during setup. The wizard is a
  *generator*, not a verifier - `--check` does that.
* No ACME / Let's Encrypt issuance. The `email` answer is only
  stored as a comment for a future integration.
* No host-package installation (`php-fpm`, `mysqldump`). See
  `install.sh`.
