# Vajra v0.14.0

**Release date:** 2026-10-12

This release packages eight weeks of work into one operator-focused
milestone. The headline feature is a **single binary that configures,
validates, and runs a WordPress site** — with WP-CLI, auto-backup, and
a deep config checker built in.

## Highlights

### Configure: `vajra setup`

An interactive wizard that generates `/etc/vajra/app.toml` for a fresh
WordPress deployment. Asks a handful of questions (domain, email, PHP
version, redis, backups, rate limit), writes the file, refuses to
overwrite without confirmation. See `docs/setup.md`.

### Validate: `vajra --check`

Deep validation of a config file without starting the server. Checks
PHP-FPM socket reachability, DB host:port, TLS cert expiry, admin
exposure, worker counts, backup paths. Prints a structured
error / warning / info report; exit code 1 on any error. See
`docs/check.md`.

### Run: the server

HTTP/1.1, HTTP/2, HTTP/3 (QUIC), WebSocket tunnels, TLS via rustls,
static files, reverse proxy, FastCGI/PHP-FPM, per-core LRU cache,
on-the-fly compression, rate limiting, access control, security
headers, Prometheus metrics. No async runtime — worker threads drive
io_uring directly.

### Operate: WP-CLI + backup

- `vajra wp <args...>` — WP-CLI wrapper that runs `wp` as `www-data`.
  `vajra-wp` shim installed by `install.sh`.
- `vajra backup` — auto-backup with a scheduler thread inside the
  server, local and S3 destinations, `mysqldump` + `tar` + `zstd`, and
  Prometheus metrics.

## Upgrading

```sh
git fetch --tags
git checkout v0.14.0
cargo build --release
sudo ./install.sh --bin=target/release/vajra
```

Config schema is unchanged from v0.13.0. `Cargo.toml` version finally
matches the tag history (`0.10.0` → `0.14.0`).

## Known limitations

- Not independently audited. See `SECURITY.md`.
- `[admin].listen` has no authentication or TLS; bind to loopback.
- No top-level `LICENSE` file in the tree (Cargo declares
  `MIT OR Apache-2.0`).
